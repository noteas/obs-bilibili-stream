# 备流、多协议、断流恢复只展示线路，插件不驱动第二路推流

OBS 单实例只有一路流输出；插件自身不驱动第二路推流，也不做“同时双推”功能。

- **备流**：官方的主备双通道（`backup_stream=1` 下发 `protocols_backup[]`，是第二条独立推流通道，有自己的地址与推流码，可与主流同时推，主流失效时 CDN 侧自动生效）。插件只把主/备线路一并展示，由用户决定如何填入 OBS 或是否自行配置第二路输出。
- **多协议**：`protocols[]` 里的协议/提供方/地址原样展示；插件不排序、不选择、不把协议映射成 OBS 服务类型。
- **断流恢复**：取回可推地址后同样只展示；插件不改 OBS 配置、不自动重推。
- 插件不改写 OBS 配置（ADR-0005）；联播（`multi_screen_*`）、连麦、ARTC/WHIP 实施明确不做。

> 备流不是“同一把密钥的多个地址”：同一 stream key 开第二个连接会被服务端拒绝。插件展示的每条备流线路都有自己的地址与推流码。
