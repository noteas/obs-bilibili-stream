# 开播与推流是两条独立轴,插件只改写服务

直播房间的开合(startLive/stopLive 信令)与 OBS 的推流输出是两件事:插件负责前者,~~并把开播所得的推流目标经 `obs_frontend_set_streaming_service`+`obs_frontend_save_streaming_service` 半自动写入 OBS 服务配置~~(2026-11-25 已由 ADR-0005 推翻:插件不改写 OBS 配置,线路只读展示);"开始推流"永远是用户在 OBS 点的那一个按钮,插件从不代点(`obs_frontend_streaming_start` 不使用)。这样"房间打开"与"画面上线"分离,每次换地址都有人工确认位。
_Avoid_ 风险:恢复/备流/换协议等一切"换地址"功能都建立在本轴的改写管线上,若将来想全自动,须先修订本 ADR。

> **2026-11-25 修订(ADR-0005)**:"插件把推流目标写进 OBS 服务配置"这一半被推翻——插件不再改写 OBS 配置,线路只读展示、用户手动填写。本 ADR 仍然有效的部分:房间开合(信令)与推流输出是两条轴,插件从不点 OBS"开始直播"。
