# MSVC 专有 Qt 符号 allowlist:只在 Windows(PE)审计时与 qt-symbol-allowlist.txt 合并生效,
# tests/check_qt_symbols.py 用。粒度同样是「类::成员」。
#
# 为什么同一条 dock.cpp 在 Windows 上会多出近两百个引用:
#   1) vftable 归属规则不同。Itanium ABI(GCC/Clang)把类的 vtable 放在「关键函数」所在的
#      翻译单元,Qt 类的关键函数在 Qt 自己的库里,插件只导入一个 vtable for QLabel;
#      MSVC 则在每个用到该类的翻译单元本地生成 vftable(dllimport 的类在本翻译单元里没有
#      任何虚函数定义),该类虚表的每个槽位于是都成了导入符号(下面的甲类,189 项)。
#   2) MSVC 对 dllimport 类的头文件内联成员不保证内联,会直接调用 DLL 导出的那份;
#      GCC/Clang 一律就地内联,不产生引用(乙类,6 项)。
# 这两类在 Itanium 平台分别由主名单的 类::vtable 一项与内联展开覆盖,不代表插件多调了 API。
#
# 核对口径(2026-11-28):每一行对照过 Qt 6.2.4 msvc2019_64 的 Qt6Core/Qt6Gui/Qt6Widgets.lib
# (导入库全量修饰名用与脚本相同的 key_msvc 归一后比对),即与主名单相同的 Qt 下限;
# 甲类另按 Qt 6.10.2 头文件逐个确认过是所在类的虚函数。
# 改动侧栏后若 Windows job 报 NEW symbol:先确认它在下限 Qt 的导入库里存在,再加进本文件;
# 别把只在该平台出现的符号加进主名单(主名单在 Linux 上是逐个强引用核对的)。
# 格式同主名单:每行一个「类::成员」;构造/析构 = 类::类 / 类::~类。
#
