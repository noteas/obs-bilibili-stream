# 状态侧栏与会话控制器：引入 Qt Widgets（仅 dock），运行期状态归 Core::Session

**状态**：采纳（2026-11-27，用户需求：新增侧栏显示直播间当前状态与必要操作，关闭直播间二次确认，提供打开配置界面的按钮；开播按钮文本改「获取推流码」）

## 背景

ADR-0003 把全部 UI 收敛为「隐藏私有 source 的 obs_properties」，并以「不引入 Qt」为前提回避了 dock 与消息框。本次需求直接指向这两样：

- OBS 前端 API 里**没有**不依赖 Qt 的 dock 入口。以 OBS 32.2.0 源码为准（`frontend/api/obs-frontend-api.h`、`frontend/OBSStudioAPI.cpp`）：`obs_frontend_add_dock_by_id(const char *id, const char *title, void *widget)` 的第三个参数就是 `QWidget*`，实现是 `OBSDock::setWidget((QWidget*)widget)` + 右侧停靠区 + `menuDocks->addAction(dock->toggleViewAction())`；前端 API 不对外发放任何可用的内容控件（只有主窗口指针、菜单 QAction）。
- 「二次确认」在纯 obs_properties 里只能做成两段式按钮（点一次改口、再点才发），没有弹窗。

同时用户反馈「直播间信息获取不顺」，审计（见 roadmap M5）确认根因在状态层而不是端点层：刷新链重（每次刷新 ≥ 9 个串行请求）、网络抖动被当成未登录、显示的不是服务端数据、分区加载失败会死循环、OBS 重启后线路被藏起来。UI 与状态逻辑全部纠缠在 `src/ui/console.cpp` 的 1131 行里，侧栏再加一个视图只会更糟。

## 决策

1. **引入 Qt6 Widgets，但只给侧栏**：`src/ui/dock.*` 是工程里唯一包含 Qt 头的翻译单元；只用 Qt 自带信号 + lambda，不定义任何 `Q_OBJECT` 子类（构建不需要 AUTOMOC/moc）。控制台仍是 obs_properties，Qt-free 形态继续存在。构建开关 `ENABLE_DOCK`（默认 ON）。
2. **运行期状态唯一所有者 = `Core::Session`**（`src/core/session.*`）：登录态、房间态快照、线路表、忙碌标志、分区表都在这里；控制台与侧栏都是它的视图（`Session::Listener::session_changed()`），只读快照渲染、把点击转成 `Session` 动作。HTTP 仍只在 worker 线程，结果经 `Http::runAsync` 的 UI 续体回 Session。
3. **侧栏生命周期**（照 OBS 32.2 源码的时序）：
   - `obs_module_load` 里 `obs_frontend_add_dock_by_id`；此时 OBS 还没 `restoreState`，用户保存过的停靠布局照常恢复；首次加载在 `OBS_FRONTEND_EVENT_FINISHED_LOADING` 自动显示一次（`config.json: dock_introduced`），之后尊重用户布局（Docks 菜单可开关）。
   - `OBS_FRONTEND_EVENT_EXIT`（主窗口与前端回调仍有效）时 `obs_frontend_remove_dock` 摘掉 dock；`obs_module_unload` 只做兜底（前端回调此时已失效，只删自己的内容控件）。文件级指针一律 `QPointer`/清零，模块卸载后不会有回调再进插件代码。
   - `obs_frontend_add_dock_by_id`/`obs_frontend_remove_dock` **运行期解析**（`dlsym(RTLD_DEFAULT)`/`GetProcAddress`），OBS 30.0.0/30.0.1 没有这两个符号时插件退回「只有控制台」，而不是整模块加载失败。
4. **Qt 版本门禁关闭 + 符号审计**：Qt 默认给每个包含其头文件的库打版本标签（`QtCore/qversiontagging.h`，运行期 Qt 比编译期旧就 `dlopen` 失败）。插件的运行期 Qt 永远是用户那台 OBS 自带的，Windows/macOS 构建用的 obs-deps 预编译 Qt（6.9.1）比 OBS 30/31 自带的新。因此定义 `QT_NO_VERSION_TAGGING`，向下兼容改由 `tests/check_qt_symbols.py` + `tests/qt-symbol-allowlist.txt` 保证：插件引用的 Qt 符号逐个对照过 **Qt 6.2.4**（Ubuntu 22.04 + OBS 30 的运行时 Qt）的导出表；出现 allowlist 之外的新符号即审计失败。README 的「OBS 30.0 或更高」因此保持成立。

   审计的两个平台事实（2026-11-28，上游 PR 的 CI 首跑后补）：

   - **Windows 并入第二份名单 `tests/qt-symbol-allowlist-msvc.txt`，只在 PE 审计时生效。** MSVC 在每个用到 dllimport 类的翻译单元里本地生成该类的 vftable（该类全部虚函数都成为导入），且对 dllimport 类的内联成员不保证内联、会直接调用 DLL 导出的那份（如 `QString::begin`）；Itanium ABI（GCC/Clang）只导入一个 `vtable for QLabel` 并就地内联。同一份 `dock.cpp` 因此在 Windows 上多出 195 个引用（189 个 vftable 槽位 + 6 个未内联的内联成员），它们同样逐个对照过 Qt 6.2.4 的 msvc2019_64 导入库，但只放在 Windows 专用名单里：这些符号在 Linux 上出现仍算新符号。
   - **审计只在 ubuntu-24.04 与 Windows job 上跑，不在 ubuntu-26.04 上跑。** Qt 6.6 起的头文件把 `QObject::setProperty` 实现为内联转发到 `QObject::doSetProperty`（Qt 6.6 才导出，6.2.4 没有）。GCC/Clang 照此内联，所以在 Qt ≥ 6.6 头文件下编出的 Linux `.so` 引用的是 `doSetProperty`，天然只能加载到自带 Qt ≥ 6.6 的 OBS；24.04 的 Qt 6.4.2 头文件下引到的仍是 `QObject::setProperty`，这一份产物才是「OBS 30.0+/Qt 6.2.4+」承诺的载体。26.04 的 zip 本就按发行版标注（libobs 主版本也随之），审计下限对它不成立，更不能把 `doSetProperty` 放进名单。MSVC 不内联而是导入 DLL 的 `QObject::setProperty`，Windows 产物不受影响（将来 MSVC 若也内联，Windows 审计会报 `doSetProperty`）。

   本地从源码构建再分发前先跑一遍审计，macOS 尤其如此（obs-deps 的 Qt 6.9.1 + Clang 同样内联成 `doSetProperty`）：审计报 `QObject::doSetProperty` 即说明这份产物只能给自带 Qt ≥ 6.6 的 OBS 用。
5. **关闭直播间二次确认** = `QMessageBox`（与 OBS 自身 `OBSMessageBox::question` 同形：栈上构造 + `exec()`），默认按钮与 Esc 都是「取消」；确认框的 parent 是 OBS 的 dock 而不是会被重建的内容控件。OBS 仍在推流时只给「请先停止推流」的警告，不进入确认（ADR-0001：推流归 OBS）。控制台保留两段式按钮。
6. **按钮口径（用户 2026-11-27）**：开播信令的按钮文本 =「获取推流码」；停播 =「关闭直播间」；恢复 =「找回推流码」。术语表里 开播/停播 仍专指服务端信令，只是界面标签按用户口径。
7. **视图重建纪律**：状态变化不就地重建控件——`session_changed` → 0ms 单发定时器 → 统一重建，且内容签名没变就不重建。绝不在一个控件的信号还在发射时把它 `delete`（控制台历史上两次 coredump 都是这个形状），周期对账刷新也不会每分钟打掉用户正在选中的文本。

## 后果

- 构建新增 Qt6 依赖：Ubuntu `qt6-base-dev`，Windows/macOS 用 obs-deps 预编译 Qt（`buildspec.json` 的 `qt6` 条目），Flatpak 用 SDK/运行时自带的 Qt6。编译依赖只剩 libobs + libcurl 的时期结束；`-DENABLE_DOCK=OFF` 可回到 Qt-free 形态。
- ADR-0003 修订：「控制台是插件唯一 UI 载体」「前端 API 无消息框」两句作废（仅限侧栏内），其余（控制台走 obs_properties、i18n 走 obs_module_text、不引入更多 Qt 页面）不变。
- ADR-0001/0005 不变：侧栏不调用 `obs_frontend_streaming_start/stop`，不改写 OBS 推流配置；线路仍只展示（侧栏多了「复制」按钮，复制到剪贴板不等于写配置）。
- 风险与兜底：Qt 符号缺失仍可能导致整模块加载失败（没有 Qt-free 的 dock 可选），由符号审计 + CI 把关；侧栏内的全部控件用离线单测之外的无头集成 harness（`tests/harness`，真实 libobs + 真实 Qt offscreen）在 CI 上回归，含 ASan/UBSan 形态。
- 隐私：控制台/侧栏显示推流码是功能本身；但**日志**不再落任何响应体（推流码、live_key、登录 ticket、refresh_token），排查契约问题需显式 `BILI_TRACE_HTTP=1`。这条不是侧栏带来的，是同批审计的 P0（见 roadmap M5）。
